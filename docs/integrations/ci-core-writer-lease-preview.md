# CI Core — 단일 SQLite Writer 소유권 잠금(개발 프리뷰)

새 Rust Core `WriterLease`는 DB 파일별로 동일한 OS 잠금 파일(`<db filename>.ci-core-writer.lock`)을 사용합니다. Rust 표준 라이브러리의 `File::try_lock`으로 *비차단 독점 잠금*을 획득하고, 앱/명령줄 실행기 수명 전체 동안 파일 핸들을 유지합니다. 잠금 획득에 실패하거나 다른 보유자가 있다면 **무조건 실패**하고 이후 DB 초기화·쓰기·가져오기·수집을 하지 않습니다.

## 적용 경계

- 새 WatchTower Tauri 실행 시 **DB 초기화 전** 잠금을 획득합니다. 앱 종료/크래시로 파일 핸들이 닫히면 OS가 자동으로 잠금을 해제합니다.
- `--import-producer-snapshot` 명령도 DB 변경이나 `VACUUM INTO` 작업 이전에 동일한 잠금을 획득합니다.
- `ci-core-stage`는 **시험용 복사본 DB**에 대해서만 잠금을 획득합니다. 운영 원본 DB는 기존대로 읽기 전용입니다.
- 잠금 파일은 지우지 않습니다. 파일을 지우고 다시 만들면 다른 잠금을 얻어버릴 수 있으므로, 잠금 파일 *존재* 자체는 사용 여부의 근거가 아닙니다.
- 다른 DB 경로는 별도 소유권을 갖습니다. 잠금은 DB 자체의 SQLite 트랜잭션, 수동 Track 귀속, Run/Attempt 원자성, GitHub 최신성 검증을 대체하지 않습니다.

## 제한 및 운영 안전

**아직 배포나 단일 Writer 전환을 해서는 안 됩니다.** 기존에 설치된 WatchTower 0.3.40은 이 새 잠금을 사용하지 않으므로, 구버전 프로세스와 새 독립 Writer가 충돌하지 않는다고 보장할 수 없습니다. 운영 전환에는 아래 항목을 모두 확인해야 합니다.

1. 기존 0.3.40 실행 중지 및 자동 시작 해제 유지, 새 잠금을 쓰는 Tauri 프로그램/CLI만 작동하도록 버전·설치 상태 확인.
2. 원본 DB·WAL 온라인 백업과 무결성 검사, 프로젝트 2개/저장소 3개/트랙 22개 및 Run/Attempt/수동 귀속 개수 보존.
3. Headless 수집기에서 새 잠금을 사용한 **단일 Writer** 구현 및 중복 프로세스·비정상 종료·재시작 후 복구 검증.
4. 기존 Producer/Track 책임 귀속 및 오류·알림 중복 방지, 기존 UI/브리지 회귀 검사.
5. 사용자 승인 후 단계적 설치/전환 및 롤백 경로 확립.

개발 브랜치의 변경은 **운영 DB와 기존 Windows 설치본을 수정하지 않습니다.** 프리뷰 단계에서는 운영 원본에 쓰지 않고 별도 스테이징 DB만 사용합니다.
